# CI 环境特有问题调查计划 - Phase 3

## 目标
深入调查 GitHub Actions CI 环境与本地环境的差异，解决 E2E 测试在 CI 中的失败问题。

## 假设的 CI 特有问题

### 1. Xvfb 显示环境问题
- CI 使用 Xvfb (虚拟显示)
- 可能与 Electron 的 GPU/渲染有冲突
- 需要特定的启动参数

### 2. Electron 沙盒权限
- CI 环境通常以非特权用户运行
- Electron 沙盒可能需要特殊配置
- 可能需要 `--no-sandbox` 等参数

### 3. 资源限制
- GitHub Actions 有内存/CPU 限制
- 并行测试可能资源竞争
- 需要调整超时和重试策略

### 4. 时序差异
- CI 环境可能比本地慢
- 网络/文件系统延迟不同
- 需要更宽松的等待条件

### 5. 环境变量差异
- CI 特有的环境变量
- 缺少某些本地可用的工具/库
- 路径差异

## 调查步骤

### Step 1: 添加详细的 CI 诊断日志
- 记录 Electron 启动参数
- 记录 Xvfb 配置
- 记录所有环境变量
- 截图和视频记录

### Step 2: 创建 CI 专用配置
- playwright.ci.config.ts
- 针对 CI 优化的超时和重试
- 更保守的并行设置

### Step 3: Electron 启动参数优化
- 禁用 GPU
- 禁用沙盒
- 优化内存使用

### Step 4: Xvfb 配置优化
- 屏幕分辨率
- 颜色深度
- 扩展配置

### Step 5: 资源管理
- 内存限制监控
- 并行度调整
- 超时优化

## 成功标准
1. CI E2E 通过率 > 90%
2. 能够识别并记录失败原因
3. 有明确的 CI 专用配置
